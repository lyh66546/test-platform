# PR 练习说明

本次练习用于学习如何提交修改、查看差异和参与检查。只新增这份文档，不修改业务代码、运行配置或数据库文件。

## 基本概念

- 仓库：保存项目文件和修改历史的地方。
- 分支：从已有代码分出的独立修改路线。
- Commit（提交）：保存一次修改的记录。
- Pull Request 或 PR（合并申请）：请求其他人检查修改，并决定是否合并。
- Review（审查）：阅读修改、提出问题或给出意见。
- Merge（合并）：把修改纳入目标分支。

## 本次申请的方向

- 仓库：lyh66546/test-platform。
- Head（提供修改的分支）：codex/pr-practice。
- Base（接收修改的分支）：master。

这是同一仓库内的练习，不向原项目作者的仓库提交申请。创建 PR 本身不等于合并。

## 怎样查看这个 PR

1. 打开 Files changed（文件变化），确认只新增了 docs/pr-practice.md，并阅读新增文字。
2. 打开 Conversation（讨论），查看申请说明；也可以留下问题或修改建议。
3. 查看 Checks（自动检查）。只有实际配置并执行的检查才会有结果，没有检查不代表已经通过测试。
4. 练习结束后，可以保留或关闭申请；是否合并需要另行决定。

## 精简手写笔记

- 分支用于独立修改，提交用于保存修改记录。
- PR 是合并申请，不是整个项目的下载地址。
- 创建 PR 不会自动把修改合并进 master。
